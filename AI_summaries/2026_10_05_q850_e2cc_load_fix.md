# q850 E2CC Metadata Load Fix

## Result

The first project metadata file now loads successfully in the running E2CC release 1.1.0 application:

```text
/home/fgerken/CODE/thinkingearth_prototype/check_data/e2cc_exports/q850/q850.e2cc.json
```

## Failure and diagnosis

Selecting the file originally appeared to do nothing. The E2CC Kit log showed:

```text
TypeError: argument should be a str or an os.PathLike object where __fspath__ returns a str, not 'list'
```

The exception came from `metadata_sequences.py` while it processed the timestamped `sources` mapping. The generated metadata mapped each timestamp to a one-item list:

```json
"2018-06-13T12:00:00": ["./textures/prediction/2018-06-13T12-00-00Z.png"]
```

For a normal, non-mosaic `latlong` timestamped sequence, E2CC release 1.1.0 expects one path string per timestamp. Lists are used for tiled or mosaic projections.

## Correction

`scripts/export_e2cc.py` was changed to emit:

```json
"2018-06-13T12:00:00": "./textures/prediction/2018-06-13T12-00-00Z.png"
```

The existing `q850.e2cc.json` was corrected in the same way for all seven prediction frames and all seven temporary-reference frames. The corrected JSON is valid, every referenced PNG exists, and E2CC now accepts the metadata file.

The generated export directory is ignored by Git, so the exporter correction is the portable source change. Regenerated exports will use the corrected representation.

## Later texture-format finding

The metadata fix above was necessary but not sufficient. On 2026-10-06, closer inspection showed invalid sector-shaped imagery. The Kit log reported that PNG paths were rejected by the JPEG-only timestamped-sequence decoder. The apparent 2026-10-05 visual success therefore confirmed metadata, controls, and timeline behavior, not successful scientific texture decoding.

All three pressure levels were subsequently regenerated as quality-99 baseline
grayscale JPEGs matching E2CC's own weather-image encoder. Earlier live tests
appeared to become posterized during timeline updates, but the same degradation
also affected the built-in Base Satellite and ordinary UI text. It was caused by
RealVNC's automatic adaptive picture quality, not by the JPEG encoding,
Dynamic Texture, Kit, or the Blackwell GPU.

With RealVNC **Picture quality** set to **High** and **PreferredEncoding** set to
**ZRLE**, `q850.e2cc.json` loads and runs through its timeline correctly. `q925`
and `q1000` were also validated successfully with the same settings.
