# Earth-2 Interactive Visualization Plan

## Goal

Provide a public, browser-accessible visualization of precomputed model predictions using NVIDIA Earth-2 Command Center (E2CC). E2CC performs GPU rendering and is streamed to reviewers through WebRTC; model inference is not required.

## Current state

- Work is on the pushed `e2cc` branch of `thinkingearth_prototype`.
- `check_data/predictions_2018.h5` was inspected and `scripts/export_e2cc.py` was added.
- The first export contains seven aligned `q850` specific-humidity predictions and seven lead-0 temporary references. It still needs validation in E2CC.
- Raw HDF5 files and generated `check_data/e2cc_exports/` assets are excluded from Git and must be transferred separately or regenerated.

## Workstation schedule

- **2026-10-02 through 2026-10-08:** RTX PRO 6000 Blackwell Server Edition workstation.
- **2026-10-09 through 2026-10-10:** no leased workstation is currently planned.
- **From 2026-10-11 onward:** RTX 6000 Ada workstation.
- Target software environment: Ubuntu 22.04, NVIDIA driver `580.105` or newer, CUDA 13.0, Docker, NVIDIA Container Toolkit, Git LFS, Python 3.12, and `uv`.

Both GPU families are suitable. NVIDIA lists the RTX PRO 6000 and RTX 6000 Ada among the recommended GPUs for the full Earth-2 Weather Analytics blueprint; E2CC requires an RTX GPU with at least 48 GB VRAM. The Blackwell Server Edition has 96 GB and the RTX 6000 Ada has 48 GB.

## Implementation sequence

1. Build and run the unmodified E2CC reference application on the Blackwell workstation.
2. Load `q850.e2cc.json` and validate texture orientation, longitude wrapping, timeline playback, toggles, and the colormap.
3. Export and validate `q925` and `q1000`, followed by additional variables and timestamps.
4. Replace the temporary lead-0 reference with real ERA5 ground truth when available, then add error layers.
5. Enable WebRTC and test browser access locally and from another machine.
6. Package the validated viewer for an approved public GPU host with HTTPS, authentication, and TURN networking as needed.

## Moving to the Ada workstation

Treat the Ada workstation as a clean deployment. Commit and push project changes, record the NVIDIA repository commit, and transfer the ignored HDF5/export data before the Blackwell lease ends. On the Ada machine, clone both repositories and rerun setup rather than copying E2CC `_build` output, Python environments, containers, or shader caches. Then repeat the workstation and visual validation checks.

The expected migration risk is low. The likely differences are reduced VRAM/performance and a fresh shader/build warm-up, not changes to the project data or metadata.

## Initial scope exclusions

- Live model inference
- Data Federation Mesh or Earth2Studio integration beyond anything required to start the reference application
- Scalable multi-user infrastructure before the single-session viewer is validated
