# E2CC Data Inspection and Export

## Source file

`check_data/predictions_2018.h5` is a valid 191 MB HDF5 file containing one dataset named `fields` and its coordinates.

```text
fields shape: [8, 2, 1, 3, 721, 1440]
dtype: float32

axes:
  0: timestamp
  1: lead-time index
  2: ensemble member
  3: channel
  4: latitude
  5: longitude
```

- Timestamps: eight six-hourly steps from `2018-06-13 06:00 UTC` to `2018-06-15 00:00 UTC`
- Lead-time values: `0` and `1`, with one step representing six hours
- Ensemble members: one
- Channels: `q850`, `q925`, and `q1000`
- Grid: global ERA5 0.25° grid, `721 × 1440`
- Latitude: `90°` to `-90°`, north-to-south
- Longitude: `0°` to `359.75°`
- Missing data: no NaN or infinite values

The channels are ERA5 specific humidity at 850, 925, and 1000 hPa. Their source unit is `kg/kg`; the visualization uses `g/kg`. Some lead-1 predictions are slightly negative. Those values remain unchanged in the HDF5 source and are only clipped in display textures.

Both lead times are model predictions. There is no ERA5 ground truth in this file. For the prototype, lead 1 at time `t` is paired with lead 0 at time `t+1`, so both represent the same valid time. Lead 0 is explicitly labeled as a temporary reference rather than ground truth. This produces seven aligned pairs.

## Export pipeline

The exporter is implemented in `scripts/export_e2cc.py` and documented in `scripts/E2CC_EXPORT.md`.

```bash
conda run -n climate python scripts/export_e2cc.py \
  check_data/predictions_2018.h5 \
  check_data/e2cc_exports/q850
```

The pipeline:

1. Validates the HDF5 structure, grid, selected channel, lead times, and finite values.
2. Aligns lead-1 predictions with the next timestamp's lead-0 temporary reference.
3. Rolls longitude from `0…359.75°` to `-180…179.75°`.
4. Converts humidity from `kg/kg` to `g/kg`.
5. Normalizes values to a fixed `0–25 g/kg` range.
6. Writes E2CC-compatible 8-bit grayscale `1440 × 721` baseline JPEG
   textures at quality 99, matching E2CC's `RenderUint8ToImages` operation.
7. Generates E2CC `latlong` image-sequence metadata with model, checkpoint, units, timeline, and colormap information.
8. Generates a provenance manifest containing source/output checksums, value ranges, and clipping counts.

The model is shown as `Earth as a Graph`. The checkpoint is:

```text
base_swin64_grouping3_mh4_segm_low_res_learned_ups_one_head_0.01_vis_paolo
```

The first export contains seven `q850` prediction textures, seven temporary-reference textures, `q850.e2cc.json`, and `q850.manifest.json`. All textures, JSON files, paths, dimensions, and SHA-256 checksums were validated. Generated exports and HDF5 files are excluded from Git.

The first E2CC import test exposed a metadata compatibility error: the exporter mapped each timestamp to a one-item path list, while the release 1.1.0 loader expects a single path string for a non-mosaic `latlong` sequence. E2CC raised `TypeError: argument should be a str or an os.PathLike object ... not 'list'`. The exporter and current `q850.e2cc.json` were corrected to use strings. On 2026-10-05, the metadata file loaded successfully in E2CC.

The initial PNG-based layers appeared to load and their timelines advanced, but a closer visual check on 2026-10-06 showed triangular cutoffs, black sectors, and broad flat color bands. The E2CC log explained the problem: release 1.1.0 routes timestamped image sequences through a JPEG-only decoder and rejected every PNG frame. Metadata and timeline loading had succeeded, but the scientific textures had not been displayed.

The exporter was corrected to generate JPEGs and all three channels (`q850`,
`q925`, and `q1000`) were regenerated. The current 42 JPEGs are `1440 × 721`,
single-channel grayscale, baseline, quality 99, and referenced by string paths.
File existence, decoded mode and dimensions, baseline encoding, and manifest
checksums were validated.

Live E2CC validation was completed on 2026-10-06. All three metadata files load,
their seven-step timelines run correctly, and the scientific fields remain
smooth. The apparent later-frame corruption seen during earlier tests was caused
by RealVNC's adaptive display encoding, not by the RGB or grayscale JPEG content,
E2CC, or the GPU. Setting RealVNC **Picture quality** to **High** and
**PreferredEncoding** to **ZRLE** eliminated the posterization for the built-in
Base Satellite and for `q850`, `q925`, and `q1000`.
